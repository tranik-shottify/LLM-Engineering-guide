Part 1 · Foundations refresher

Part 1

Foundations refresher

Vocabulary fixed in eight pages: enough to make the rest of the document unambiguous.

1.1 Transformer architectures

Three Transformer shapes coexist, but only one dominates current LLM practice. Encoder-only stacks (the BERT family) attend bidirectionally and are used for classification, span extraction, and dense retrieval. Encoder-decoder models (T5, BART, FLAN-T5) couple a bidirectional encoder to an autoregressive decoder via cross-attention; they were the standard for sequence-to-sequence work — translation, summarization, structured generation — through about 2022. Decoder-only stacks with causal masking — every token attends only to itself and its predecessors — now power virtually all general-purpose generative LLMs. The unified next-token-prediction objective, the simpler architecture, the cleaner scaling story, and the fact that decoder-only stacks subsume seq2seq tasks under prompted generation, all combined to push the field there.

Inside any of these shapes the basic block is the same: a self-attention sublayer, a position-wise feed-forward sublayer, normalization, and residual connections. The figure below shows a modern decoder block.

1.2 Attention and its variants

The atomic operation of every Transformer is scaled dot-product attention:

$$ \operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V $$

For each query, we compute similarity against all keys, normalize via softmax, then take a weighted mix of values. The \(\sqrt{d_k}\) factor keeps the pre-softmax scores in a well-conditioned regime — without it, scores grow with the head dimension and the softmax saturates, killing gradients.

Multi-head attention runs this operation in parallel across H learned subspaces and concatenates the results. The variants below trade expressiveness against the size of the key-value cache, which dominates inference memory at long contexts.

  • MHA — Multi-head attention. Each head has its own Q, K, V projections. Maximum expressiveness, maximum KV-cache: 2 · L · H · d_h floats per layer.
  • MQA — Multi-query attention. All query heads share a single K and V projection. KV-cache shrinks by a factor of H. Quality drops measurably on hard tasks unless trained carefully.
  • GQA — Grouped-query attention. Query heads form G groups, each sharing one K/V pair. Typical ratios are 8:1 or 4:1. The default in current open-weight stacks (Llama 3, Qwen 2.5/3, Mistral) — quality close to MHA, KV-cache close to MQA.
  • MLA — Multi-head latent attention. Used by DeepSeek-V2 / V3. Compresses K and V into a low-rank latent that is cached in place of the full K/V tensors and reconstructed at attention time. Cuts KV-cache aggressively while retaining MHA-class quality.

1.3 The modern decoder block

Most contemporary open-weight LLMs are remarkably similar inside. The block uses pre-norm, applying normalization before the sublayer rather than after — pre-norm trains stably at depth without warmup tricks. The norm is RMSNorm, which omits the mean-subtraction step of LayerNorm and is meaningfully cheaper while empirically as effective.

The feed-forward sublayer is a gated variant — SwiGLU or GeGLU — of the form \(\text{FFN}(x) = (\text{Swish}(xW_1) \odot xW_2)\,W_3\). Gating consistently outperforms a vanilla GELU FFN at the same parameter count. Because the gate adds a third projection, the hidden dimension is shrunk to roughly \(\tfrac{8}{3} d_{\text{model}}\) to keep the parameter count comparable to a 4× GELU MLP.

Combined with RoPE positional encoding (Section 1.6) and GQA or MLA attention, this is the recipe shared by Llama 3.x, Qwen 2.5 / 3, Mistral, Gemma 3, DeepSeek-V3 and most of their peers — modulo MoE routing or hybrid SSM layers. The architectural search has narrowed; the differentiation is in data, scale, and post-training.

1.4 Tokenization

An LLM does not see characters; it sees integer token IDs from a fixed vocabulary. The tokenizer is therefore the model's actual "input format," and tokenization decisions outlive any model checkpoint that depends on them.

  • Byte-Pair Encoding (BPE). Iteratively merges the most-frequent adjacent symbol pair into a new token. Used by GPT-2/3/4, Llama 2, Mistral. Implemented in Hugging Face tokenizers and OpenAI's tiktoken.
  • SentencePiece. A library that treats raw text as a stream of bytes, language-agnostic, with both BPE and unigram-LM training algorithms. Standard for T5, Mistral, Gemma.
  • Byte-level fall-back. Every Unicode byte is representable as a 1-byte token, so the tokenizer cannot OOV. Standard now in nearly every production tokenizer.

Vocabulary sizes range from about 32k (Llama 2) to 128k-256k (Llama 3.x, Qwen, GPT-4o family). Larger vocabularies compress text more (fewer tokens per sentence), shrinking inference cost and stretching the effective context — but the embedding and unembedding matrices grow with vocabulary, increasing parameter count and memory.

Multilingual token economics matter. A vocabulary trained predominantly on English will spend several tokens to encode a single character of Chinese, Bengali, Arabic, or Korean text — sometimes 2-4× the English token count for the same logical content. This shows up as inflated API bills, shorter effective context, and degraded quality. Modern models with explicitly multilingual tokenizers (Qwen, Gemma 3, GPT-4o) substantially close this gap.

1.5 Special tokens and chat templates

Beyond ordinary content tokens, every modern tokenizer reserves IDs for control: BOS (begin), EOS (end / stop), PAD for batching, plus role markers for chat. The model is trained to condition on these markers; how you arrange them at inference must match how they appeared in training.

A chat template is the deterministic function that turns a list of {role, content} messages into the token sequence the model expects. ChatML uses <|im_start|>role\ncontent<|im_end|>. The Llama 3 template uses <|begin_of_text|>, <|start_header_id|>...<|end_header_id|>, <|eot_id|>. Qwen, Mistral, and Gemma each have their own.

Pitfall — wrong chat template, silent regression

Using the wrong template (or hand-formatting strings instead of calling tokenizer.apply_chat_template(messages, add_generation_prompt=True)) often produces output that looks reasonable but is measurably worse on instruction-following and refuses to stop cleanly. The model never raises an error — it just regresses. Always derive the prompt from the tokenizer that ships with the checkpoint.

1.6 Positional encodings

Self-attention is permutation-equivariant; positional information must be injected explicitly.

  • Absolute (sinusoidal or learned). Add a position vector to each token embedding (original Transformer, GPT-2/3). Does not extrapolate beyond trained lengths.
  • RoPE — Rotary Position Embedding. Rotates each Q and K vector by a position-dependent angle in 2D subspaces of the head. Encodes relative position implicitly via the inner product. Dominant in current open-weight LLMs.
  • ALiBi. Adds a linear, head-specific bias to attention scores proportional to query-key distance. Pure extrapolation, zero training cost beyond the bias slope.
  • YaRN, NTK-aware, dynamic NTK, ABF. Techniques for extending RoPE-trained models to longer contexts than their pretraining window by rescaling the rotary base frequency. Standard for taking a 4k-8k pretrained model to 32k-128k+ with a short continued-pretraining stage.

1.7 From logits to loss

The final layer maps the last hidden state to vocabulary-size logits; softmax converts logits to a probability distribution; the training objective is the negative log-likelihood of the next token. For a sequence of length \(N\):

$$ \mathcal{L}_{\text{CE}} = -\frac{1}{N} \sum_{t=1}^{N} \log p_\theta(x_t \mid x_{\lt t}) $$

Perplexity is the exponentiated per-token loss:

$$ \operatorname{PPL} = \exp(\mathcal{L}_{\text{CE}}) $$

Perplexity has a direct probabilistic reading: the effective branching factor over the vocabulary. Lower is better, with 1.0 being perfect prediction. Perplexity is a useful comparator only across models sharing a tokenizer; cross-tokenizer comparisons are meaningless without a normalization step.

1.8 Training objectives

  • Causal LM. Predict each next token given prior tokens. The objective for decoder-only LLMs and the dominant pretraining task today.
  • Masked LM. Mask roughly 15% of input tokens and predict them from bidirectional context (BERT). Yields strong representations, weak generators.
  • Span corruption. Replace contiguous spans with sentinel tokens; predict the spans (T5). Encoder-decoder objective.

1.9 Sampling and decoding

At inference the model emits a logit vector at each step; the decoder turns that into the next token.

  • Greedy. Argmax. Deterministic, prone to repetition loops, often dull on open-ended generation.
  • Beam search. Maintain top-k partial hypotheses; useful for short structured outputs (translation, constrained generation), counter-productive for open-ended chat where it produces bland, mode-seeking text.
  • Temperature. Scale logits by \(1/T\) before softmax. \(T<1\) sharpens, \(T>1\) flattens. \(T=0\) collapses to greedy.
  • Top-k. Keep the k most-probable tokens, renormalize, sample.
  • Top-p (nucleus). Keep the smallest set of tokens whose cumulative probability meets p. The de facto default.
  • Min-p. Keep tokens with probability \(\geq p \cdot p_{\max}\). More stable than top-p across confidence regimes; handles the "the next token is obvious" case well.
  • Typical sampling. Prefer tokens whose surprisal is near the conditional entropy. Less aggressive about clipping the long tail than top-p.
  • Repetition / frequency / presence penalties. Subtract a fixed amount (or scale) from the logits of recently emitted tokens. Cheap fix for literal loops; aggressive values harm fluency.
  • Contrastive decoding. Subtract a weak "amateur" model's log-probabilities from a strong "expert" model's, suppressing the easy-but-bland continuations both agree on.

1.10 Scaling laws

The early scaling-laws work (2020) established that test loss falls as a power law of model size, dataset size, and compute, with overlapping but separable exponents. The Chinchilla scaling-laws update (2022) re-derived the compute-optimal trade-off: for a fixed compute budget, parameter count and training tokens should grow together, with roughly 20 tokens per parameter at the optimum. Earlier large models (GPT-3, OPT, MT-NLG) were sharply under-trained on data relative to their size; the Chinchilla model itself outperformed Gopher at four times fewer parameters.

Modern open-weight LLMs aim well past Chinchilla-optimal because inference cost scales with parameters and not with the tokens used to train them. A small model trained on far more tokens than its compute optimum is cheaper to serve forever than a larger model trained on fewer. Llama 3 8B was trained on roughly 15 trillion tokens — two orders of magnitude beyond Chinchilla optimum for its size — and the result is a small model that performs far above what its parameter count would predict.

1.11 In-context learning and prompting primitives

Treat these as part of the foundation, not as a separate "prompt engineering" discipline.

  • Zero-shot. Instruction only; relies on instruction tuning.
  • Few-shot. Several in-context examples before the actual query. Effective when task format is unusual or label space is non-obvious.
  • Chain-of-thought (CoT). Eliciting intermediate reasoning steps with example traces or "let's think step by step." Effects diminish or invert for reasoning-tuned models that already CoT internally — explicit "think step by step" can hurt.
  • Role-message structure. Use the system / user / assistant channels as designed; bury task-invariant constraints in the system message, query in the user message.
  • Templates. Treat prompts as parameterized objects with versioning and tests, not as ad-hoc strings.

1.12 Embeddings

An embedding here means a fixed-dimensional vector summary of a piece of text, used for semantic search, clustering, classification heads, or retrieval-augmented generation.

  • Bi-encoder. Encode query and document independently; score by similarity. Allows offline indexing and approximate nearest-neighbor search at scale.
  • Cross-encoder. Concatenate query and document and run them through the model jointly to produce a single relevance score. Far more accurate than a bi-encoder, but quadratic in the candidate set — used as a reranker over a small bi-encoder shortlist.
  • Dimensionality. Production embeddings range from 256 to 4096 dimensions. Matryoshka representation learning trains the same vector to be useful when truncated to smaller prefixes — a single 1536-dim embedding can serve as a 256, 512, or 1024-dim embedding without re-encoding.
  • Similarity measures. Cosine similarity (angle-only) is the default. Dot product (angle plus magnitude) is used when magnitude carries meaning. Euclidean distance is interchangeable with cosine after L2 normalization.

1.13 Context window vs effective context

Advertised context windows have raced past 1M tokens, with some experimental models claiming 10M+. Usable context lags well behind. Three observations matter for engineering decisions.

  • Lost-in-the-middle. Models retrieve and reason from material at the start and end of a long context far better than from the middle. Important context belongs near the boundaries.
  • Needle-in-a-haystack vs multi-needle. A model that scores 100% on single-needle retrieval may collapse on multi-needle, multi-hop, or reasoning-over-context tasks.
  • Effective context is empirical. Treat advertised context as a soft upper bound; measure on representative tasks. A reasonable working assumption is 25-50% of the advertised window for accurate reasoning, lower for some models, higher for the strongest. Validate before architecting around long context.
Part 2 · Modern model landscape

Part 2

Modern model landscape (2025-2026)

The current model zoo, sorted by what is actually shipping in production rather than by leaderboard position.

The model space partitions cleanly into open-weight families you can self-host, frontier closed APIs, reasoning-specialized models that consume far more compute per query, alternative architectures challenging dense Transformers, and small models tuned for the edge.

2.1 Open-weight families

  • Llama 3.x and 4 (Meta). The 3.x line spans roughly 1B, 3B, 8B, 70B, and 405B dense parameters; Llama 4 introduced Mixture-of-Experts variants and natively multimodal designs. Wide tooling support, permissive license with named-user thresholds.
  • Qwen 2.5 / 3 (Alibaba). Sizes from sub-1B through tens of billions, plus large MoE configurations. Strong multilingual coverage — particularly Chinese — and competitive with Llama on most English benchmarks.
  • Mistral and Mixtral. Mistral 7B remains a workhorse small model; Mixtral 8×7B and 8×22B were the breakout open MoE designs. Newer flagship Mistral models have moved to closed weights.
  • Gemma 3 (Google). Open-weight sibling line to Gemini, multimodal at the larger sizes, multilingual focus.
  • Phi-4 (Microsoft). The "small but punchy" line, trained heavily on synthetic and curated data; consistently outperforms its parameter count on reasoning benchmarks.
  • DeepSeek-V3. Large MoE with MLA attention and DeepSeekMoE routing; reaches frontier quality at a fraction of dense-model serving cost.
  • DeepSeek-R1. Reasoning model derived from V3 via RL on verifiable rewards; the open-weight reference for inference-time-compute reasoning.
  • Command-R / R+ (Cohere). Optimized for enterprise retrieval-augmented generation and tool use; structured-output and citation behavior baked in.

2.2 Frontier closed models

  • GPT-5 family (OpenAI). The successor line to the GPT-4 generation. Reasoning is on by default at the upper tiers; multimodal across text, image, and audio.
  • Claude 4.x family — Opus, Sonnet, Haiku (Anthropic). Tiered by capability and cost. Strong on coding, long-form analysis, and instruction adherence. Constitutional AI-derived alignment.
  • Gemini 2.5 (Google). Native multimodal across text, image, audio, and video, with very long context windows and tight integration into Google's tooling ecosystem.

2.3 Reasoning models and test-time compute

A new model class — exemplified by OpenAI's o1 and o3, DeepSeek's R1, and Qwen's QwQ — produces an extended internal chain of thought before committing to a visible response. Quality scales with the number of "thinking tokens" the model is allowed to spend; cost scales the same way.

Test-time compute is justified for problems that meaningfully benefit from search and verification — competition math, multi-step proofs, code with non-trivial constraints, agentic planning under uncertainty. It is not justified for extraction, classification, simple Q&A, or anything latency-sensitive: the cost premium is large and the quality lift is small or zero.

2.4 Architectures beyond dense Transformers

  • Dense Transformers. All weights activate for every token. Predictable throughput, predictable cost, the easiest to serve.
  • Mixture-of-Experts (MoE). Many feed-forward "experts" per layer; a router selects a small top-k (typically 2-8 of 16-256) per token. Inference cost is governed by active parameters, not total — DeepSeek-V3 has ~671B total parameters but ~37B active. Training is harder (load-balancing losses, expert collapse), serving is harder (memory still scales with total parameters; routing imbalance kills throughput).
  • State-Space Models (Mamba, Mamba-2). Selective state-space layers process sequences in linear time with fixed-size hidden state — no attention, no quadratic cost in sequence length. Compelling for very long inputs; on shorter inputs they trail strong attention models on recall and in-context learning.
  • Hybrid stacks. Alternate SSM and attention layers to retain attention's ICL strengths while gaining SSM's long-context economics. Jamba, Zamba, and several recent open-weight releases use this pattern; the Pareto frontier favors hybrids over pure SSM.
  • Diffusion language models. Generate sequences by iterative denoising rather than left-to-right autoregression. They trade latency against throughput differently — parallelizable across positions, but require multiple denoising steps per output. Still early; not yet mainstream for general-purpose chat.

2.5 Small Language Models and on-device deployment

SLMs target latency, privacy, offline use, and cost rather than chasing the leaderboard. The Phi family demonstrated that aggressive synthetic-data curation lets a billion-parameter model match older 7B-class models on reasoning. Gemma-nano targets sub-1B on-device serving; Llama 3.2 1B and 3B are designed for edge deployment.

SLMs work well for narrow, well-specified tasks — extraction, classification, structured rewriting, function-call decision — and for environments where round-tripping to a cloud API is unacceptable. They struggle on open-ended reasoning and on knowledge-intensive prompts where parameter capacity is the binding constraint.

Key idea — pick by binding constraint, not by leaderboard

The right model for a system is the smallest one that meets the quality bar on representative evals at acceptable latency and cost. Frontier closed for hard reasoning when the capability is the constraint; mid-size open-weight for a tunable, self-hostable workhorse; SLM for edge or strict cost ceilings; reasoning model only when the task actually rewards extra thinking tokens.

Part 3 · Adapting models

Part 3

Adapting models — SFT, PEFT, alignment, distributed training

From a base checkpoint to a deployable instruction-tuned model: every knob, every trade-off, and the failure modes that bite you in week three.

3.1 Choosing the right adaptation stage

Three adaptation regimes, ordered by intensity:

  • Continued pre-training (DAPT — domain-adaptive pre-training). Run the next-token-prediction objective on a large unlabeled domain corpus to shift the model's intrinsic distribution. Use this when you have a serious distributional gap from the pretraining data — legal text, biomedical text, low-resource languages, a specialized programming language — and a corpus measured in billions of tokens. Expensive; risks catastrophic forgetting of general ability.
  • Supervised fine-tuning (SFT — also called instruction tuning). Train on demonstration pairs (prompt, completion) with the standard LM loss, usually masked to the completion only. The cheapest large-effect lever: a few thousand to a few hundred thousand high-quality examples reshape style, format, and task behavior.
  • Preference optimization. Train on pairs (or rankings) of better and worse completions for the same prompt to refine tone, helpfulness, safety, and adherence to subtle constraints SFT cannot teach from demonstrations alone.

The canonical pipeline is pretrain → SFT → preference optimization, optionally followed by a safety-focused pass (RLAIF or constitutional revision). Skip the first stage if your task does not need a knowledge shift. Skip the third if SFT alone meets the bar — most narrow tasks do not need preference tuning.

3.2 Loss masking in SFT

The single most common SFT bug: training the cross-entropy loss on the prompt tokens as well as the response. The fix is to construct a labels tensor in which all prompt-position labels are set to PyTorch's ignore index (-100), so gradient flows only through the response tokens. Forgetting this wastes capacity on memorizing the prompt distribution and degrades response quality measurably.

Hugging Face's SFTTrainer exposes a chat-template-aware assistant_only_loss path (and the DataCollatorForCompletionOnlyLM equivalent) that does the masking for you when you supply the conversation in the standard {role, content} format. Hand-rolled tokenization paths must implement the masking explicitly.

3.3 Parameter-Efficient Fine-Tuning (PEFT)

Full fine-tuning a 70B-parameter model requires the optimizer states, gradients, and master weights for every parameter — at bf16 mixed precision with Adam, that is roughly 16 bytes per parameter, or about 1.1 TB of GPU memory before activations. PEFT methods freeze the base weights and train a tiny number of new parameters, slashing memory and storage.

  • LoRA. For a frozen weight \(W \in \mathbb{R}^{m \times n}\), introduce a low-rank update \(\Delta W = BA\) with \(B \in \mathbb{R}^{m \times r}\), \(A \in \mathbb{R}^{r \times n}\), \(r \ll \min(m,n)\). Only \(A\) and \(B\) train. Typical ranks are 8-64. Trainable parameters: roughly 0.1-1% of the base model.
  • QLoRA. LoRA applied on top of a 4-bit NF4-quantized base, with double-quantization of the quantization constants and paged optimizer states. Fits a 70B fine-tune into a single 48-80 GB GPU. The dominant approach for hobbyist and small-team fine-tuning.
  • DoRA — Weight-Decomposed Low-Rank Adaptation. Decomposes the pretrained weight into a magnitude vector and a direction matrix; trains the direction with a LoRA-style low-rank update and the magnitude separately. Closes much of the quality gap to full FT at the same trainable-parameter count.
  • AdaLoRA. Allocates the rank budget across layers adaptively using SVD-based importance scoring during training. More parameter-efficient than fixed-rank LoRA.
  • LoftQ. A LoRA initialization scheme for quantized bases — finds the low-rank residual that minimizes the quantization error of the frozen base, giving the LoRA adapter a meaningful starting point rather than zero.
  • IA³ — Infused Adapter by Inhibiting and Amplifying Inner Activations. Learns three vectors that scale the keys, values, and FFN intermediate activations. Even fewer parameters than LoRA, lower quality ceiling — useful for many-task multi-tenancy where adapter size dominates storage.
  • Prompt tuning / prefix tuning. Train soft tokens prepended to the input embedding (prompt tuning) or to every layer's keys and values (prefix tuning). Underperforms LoRA for serious adaptation; rarely used today except in very small models.

3.4 Alignment: turning a base model into a useful one

SFT teaches format and task; preference optimization teaches taste — which of two acceptable answers is preferred, and by how much. The history runs from RLHF through a sequence of progressively simpler losses.

  • RLHF with PPO. Train a reward model on human preference pairs, then optimize the policy with Proximal Policy Optimization, with a KL-divergence penalty against the SFT reference policy to prevent drift. Powerful, infamously brittle: reward hacking, reward-model overfitting, and PPO instability all conspire against you.
  • DPO — Direct Preference Optimization. Algebraically rearranges the RLHF objective to remove the explicit reward model: under the Bradley-Terry preference model and with the same KL anchor, the optimal policy is a closed-form function of the preferences and the reference, so you can fit it directly. Loss:
$$ \mathcal{L}_{\text{DPO}}(\pi_\theta;\,\pi_{\text{ref}}) \;=\; -\,\mathbb{E}_{(x, y_w, y_l)\sim\mathcal{D}}\!\left[\, \log \sigma\!\left(\beta \log\frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} \;-\; \beta \log\frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right) \right] $$

Here \((x, y_w, y_l)\) is a prompt with a winning and losing completion, \(\pi_{\text{ref}}\) is the SFT model, and \(\beta\) controls how strongly the policy can deviate from the reference. DPO is the current default starting point — simpler than PPO, two-thirds the moving parts.

  • IPO — Identity Preference Optimization. Replaces DPO's logistic loss with a squared loss on the implicit reward gap, mitigating DPO's tendency to over-fit on near-deterministic preferences and run the implicit reward to ±∞.
  • KTO — Kahneman-Tversky Optimization. Operates on unpaired thumbs-up / thumbs-down signals rather than pair preferences, modeling utility with a prospect-theory-flavored asymmetry. Useful when your data pipeline naturally yields unary feedback rather than head-to-head comparisons.
  • ORPO — Odds Ratio Preference Optimization. Combines the SFT loss and a preference signal in a single training stage, eliminating the reference model entirely. Memory-cheap, simple, surprisingly competitive — good fit for small-team setups.
  • SimPO. Length-normalized preference loss without a reference model. Cheap and stable; closes much of the gap to DPO without the KL anchor.
  • RLAIF — RL from AI Feedback. A larger model labels preferences in place of human raters. Quality of the resulting policy tracks the labeler's judgment closely; pairs well with curated rubrics.
  • Constitutional AI. The model critiques and revises its own outputs against a written constitution, generating preference pairs (original vs revised) that drive the alignment stage. Removes much of the human labeling cost from safety alignment specifically.

3.5 Synthetic data pipelines

The marginal value of an extra good training example is large; the marginal value of an extra bad one is negative. Modern post-training leans heavily on synthetic data generation precisely because curation, not collection, is the binding constraint.

  • Distillation. A strong teacher model generates traces — answers, chains of thought, tool-use trajectories — that a smaller student is trained to imitate. The dominant pattern for producing capable small models.
  • Self-instruct. Bootstrap an instruction dataset by prompting the model to generate new instruction-response pairs from a small seed set, then filter for quality.
  • Evol-instruct. Iteratively complicate prompts in a controlled way — deepen, broaden, add constraints, increase reasoning steps — to produce harder training examples than the seed pool contains.
  • Self-rewarding. The model alternates between acting as policy and as judge; preferred outputs (by the model's own judgment) feed the next preference-tuning round. Scales preference data generation but propagates the model's biases into its own training signal.

3.6 Distributed-training primer

Once a model no longer fits on a single GPU, or once you want to shrink wall-clock time, you reach for parallelism. Each scheme shards a different dimension; production training stacks combine several.

  • DDP — Distributed Data Parallel. Replicate the full model on every GPU; each GPU processes a different micro-batch; gradients synchronize via all-reduce. Limit: the entire model, optimizer states, and activations must fit on one device.
  • ZeRO-1. Partition optimizer states across data-parallel ranks. Cuts the largest memory consumer (Adam's two moment buffers) by the world size.
  • ZeRO-2. Add gradient partitioning. Gradients are reduced-scattered rather than all-reduced.
  • ZeRO-3 / FSDP — Fully Sharded Data Parallel. Add parameter partitioning. Each rank holds only its shard of weights; full layers are gathered just-in-time for the forward and backward pass, then released. The standard way to train large models when you have many GPUs but cannot afford tensor-parallel network bandwidth.
  • Tensor Parallel (TP). Split individual matrix multiplications across devices (Megatron-LM style — column-parallel for QKV projections, row-parallel for output projections). Communication-heavy; almost always run within a single node over NVLink.
  • Pipeline Parallel (PP). Split layers into stages on different devices; pipeline micro-batches through them. Introduces a "bubble" — idle time at the start and end of the pipeline — that is partially hidden by the 1F1B or interleaved schedules.
  • Sequence Parallel (SP). Shard the sequence dimension of activations. Pairs naturally with TP to cut per-device activation memory at long contexts.

In practice, large-scale training combines these: FSDP for parameters, TP within a node for the largest layers, PP across nodes when the model exceeds a single node's memory, and SP when context length is the bottleneck. The right configuration depends on model size, batch size, sequence length, and the network topology you actually have.

Auxiliary techniques that are nearly always on:

  • Mixed precision: bf16 is the default for training. It has the same exponent range as fp32 — no loss-scaling required, no overflow surprises. fp16 is cheaper on older hardware but needs careful loss scaling and is brittle at scale.
  • Gradient accumulation. Accumulate gradients over k micro-batches before stepping; simulates a global batch size k× the per-step batch.
  • Gradient checkpointing (a.k.a. activation checkpointing). Recompute selected activations during the backward pass instead of storing them. Costs roughly 30% extra compute, saves on the order of 50%+ activation memory; required for long-context training.
  • Activation offloading. Stash activations in CPU memory or NVMe between the forward and backward pass. Saves GPU memory at the cost of PCIe bandwidth — used selectively, on the largest activations.

3.7 Model merging

Once you have several fine-tuned variants of the same base, you can sometimes get a better model than any individual one by combining their weights — without further training.

  • Task-vector arithmetic. Define each fine-tune's task vector as \(\tau_i = \theta_i^{\text{ft}} - \theta^{\text{base}}\). Combine by adding scaled task vectors back to the base: \(\theta' = \theta^{\text{base}} + \sum_i \alpha_i \tau_i\). Subtraction can remove a behavior.
  • TIES — TrIm, Elect Sign, Disjoint Merge. Sparsifies each task vector, resolves sign conflicts across vectors by majority vote, and averages only the agreeing entries. Reduces interference when merging adapters that pull in different directions.
  • DARE — Drop And REscale. Randomly drops a fraction of each delta and rescales the survivors to compensate. Often a near-loss-free compression, sometimes a quality boost.
  • SLERP — Spherical Linear intERPolation. Interpolates two checkpoints along the great circle on a hyper-sphere rather than the chord. Often outperforms naive linear averaging on two-model merges.
  • MergeKit. The standard tooling. Recipe-driven YAML; supports all of the above plus Frankenmerges (interleaving layers from multiple models).

3.8 Practical fine-tuning tooling

The community has converged on a small stack. Pick by team size and operational maturity, not by feature checklist.

  • Hugging Face peft + accelerate. The foundational layers — adapter implementations, multi-GPU launchers, FSDP / DeepSpeed integration. Almost everything else sits on top.
  • TRL. SFTTrainer, DPOTrainer, KTOTrainer, ORPOTrainer, GRPOTrainer. The default Python API for post-training.
  • Axolotl. YAML-driven training stack with first-class LoRA / QLoRA / FSDP / DeepSpeed support. The de facto choice for community fine-tunes.
  • Unsloth. Custom Triton kernels and memory tricks; roughly 2× the throughput of vanilla TRL for LoRA / QLoRA SFT and DPO on supported architectures.
  • LLaMA-Factory. Web UI plus CLI; broad coverage of methods. Useful for teams that want to expose fine-tuning to non-engineers.

3.9 A minimal SFT recipe

The snippet below is a complete LoRA SFT setup using peft and trl — the smallest configuration that is actually useful in practice.

from datasets import load_dataset
from peft import LoraConfig
from transformers import AutoModelForCausalLM, AutoTokenizer
from trl import SFTConfig, SFTTrainer

model_id = "meta-llama/Meta-Llama-3-8B"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="bfloat16")

lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"], task_type="CAUSAL_LM")

dataset = load_dataset("HuggingFaceH4/ultrachat_200k", split="train_sft")
args = SFTConfig(output_dir="./sft-llama3-lora", learning_rate=2e-4, bf16=True,
    per_device_train_batch_size=4, gradient_accumulation_steps=4,
    max_seq_length=2048, packing=True, assistant_only_loss=True)

trainer = SFTTrainer(model, args=args, train_dataset=dataset,
                     peft_config=lora, processing_class=tokenizer)
trainer.train()

3.10 The alignment pipeline end-to-end

The pieces connect into a recognizable assembly line. Pretraining produces a base model; SFT shapes it into an instruction-follower; preference optimization tunes its taste; an optional safety pass enforces hard constraints.

3.11 Failure modes

  • Catastrophic forgetting. Post-training degrades unrelated abilities — the freshly SFT-tuned model can no longer write Python, or has lost a language. Mitigations: a replay buffer of pretraining data mixed into post-training, lower learning rates, LoRA (which constrains drift to the adapter), or explicit regularization toward the reference model (which DPO and PPO do automatically via their KL term).
  • Reward hacking. The policy discovers an exploit of the reward model that scores high but fails the underlying intent — verbose answers that pattern-match "helpfulness," confident wrong answers that the reward model cannot distinguish, sycophancy. Mitigations: KL anchoring, ensembles of reward models with disagreement penalties, frequent reward-model retraining on adversarial samples, and out-of-distribution monitoring.
  • Alignment tax. Aligned models score lower on raw capability benchmarks than their base counterparts. Some of this is inherent (safety constraints exclude valid completions); some is mitigable by mixing capability data into the preference stage so the gradient is not purely shaped by stylistic preferences.
  • Mode collapse. Outputs lose diversity — the model produces near-identical responses to varied prompts. Particularly common with aggressive DPO. Mitigations: lower \(\beta\), length normalization (SimPO), mixing the SFT loss into the preference stage (ORPO-style), or capping training to fewer epochs.
Senior tip — eval-driven adaptation

Instrument the eval suite before you touch any training code. Run it on the base model to set the floor; run it after every fine-tuning experiment; track both target metrics and capability regressions on a held-out set of pretraining-style tasks. The gradient of the loss does not measure what you actually care about; only the eval suite does. The fastest fine-tuning teams iterate on the dataset, not on the optimizer.
